1 架构总览

CHEAV 是纯静态页面：没有打包器、没有 node_modules，所有脚本以普通 <script> 按顺序加载。index.html 直接双击即可运行。

路径职责
index.html页面骨架、加载顺序、缓存标记（?v=3.0.0）、页脚版本
js/plugin/MdCRndr.js内置 MdC 渲染引擎（可独立嵌入），含解析、排版、VRG、连字、方框
js/plugin/mdc*.jsMdCRndr 的编码 / 度量 / 视图 / 围框 / VRG / 字形核心等子模块
js/render/jsesh-render.jsjsesh-js 适配层：初始化、码规范化、单码快速渲染、错误检测
lib/jsesh/jsesh-js 0.2.0（CeCILL-C）+ data/ 字形数据（约 24 MB）
js/database/词表、音素表、定符表、键位、语言、设置
js/engine/匹配（音素/码/词）、渲染入口、MdCRndr 初始化
js/ui/IB、三个候选区、正文、设置、文档浮层、缩略图
data/dickson/Dickson 词典派生词表（CC BY-NC-SA 2.5，见第 3 节）
tools/词典反推 / 词表生成等离线脚本（不参与页面运行）

加载顺序（index.html）

mdcGlyphTables → ngMetrics → svgBoxes → mdcEncoding → mdcMetrics → mdcView
→ mdcEnclosure → mdcVrg → mdcCadrat → mdcGlyphCore → MdCRndr
→ database/*（词表、音素、定符、键位…）
→ data/dickson/vocabulary-dickson.js（可选，缺失时静默跳过）
→ engine/* → ui/* → boot
改动任何脚本后，记得同步改两处：index.html 的 ?v=3.0.0 缓存标记，以及 js/ui/glyphs.js 里的 BUILD 常量（页脚 Build 显示它）。

2 渲染管线

2.1 首选：jsesh-js 适配层

js/render/jsesh-render.js 暴露一个全局 JseshRender：

成员说明
init()动态 import() lib/jsesh/jsesh.js，configureJSesh({glyphsUrl})，并预取 glyph-index.json
svgFor(mdc, cadratHeight, opts)整串 MdC → SVG 字符串；opts.vertical 走竖排
glyphSvg(code, cadratHeight)单码快速通道：直接取字形路径拼 SVG，不跑排版引擎（7 码约 10 ms）
fixCode(code)CHEAV 写法 → jsesh 写法（AA1→Aa1、M17a→M17A、Y1a/Y1A→Y1v），按字形索引校验
normalize(mdc)对整串里的码逐个 fixCode，保护 <文本> 段
supports(mdc)拒绝 %insert、%hkern、%vkern（jsesh 未实现）
ready / lastError是否已初始化 / 最近一次错误文本

错误处理

jsesh 解析失败时会把 Error in file: 逐字符输出成 <text>，因此适配层会去掉标签与空白后再匹配这段文字，得到“第 X 行第 Y 个字符附近”的提示。渲染失败时保留上一次的成功渲染，错误只写进“解析错误”条，不清空渲染区。

2.2 回退：内置 MdCRndr

设置里可切换渲染引擎；jsesh 不可用或整串含未实现构造时，回退到 MdCRndr。两条路径都用 SVG 字形，不再依赖 NewGardiner 字体。

2.3 缩略图的三条路径

条件路径
页面有 glyfs/（本地开发）Thumbs：按码查本地 SVG 缩略图
无 glyfs/（GitHub Pages）JseshRender.glyphSvg → 失败再 svgFor
jsesh 不可用MdCRndr.renderText

缺字形统一显示红色码文本（例如 A478A），与 JSesh / 词典原书一致；不要改回方块或斜纹占位。

2.4 竖排

jsesh 的竖排不是 %[orientation=vertical]，而是 renderMdc(mdc, { style: { options: { textOrientation: "VERTICAL" } } })。CHEAV 的竖排按 7 列、列间距与字号联动计算。

4 匹配、候选与性能

4.1 单元池

  • PHONEME_UNITS：音素表 + JSesh 键盘转写候选（已按 l1|l2 去重）；
  • 定符单元：来自 determinatives.js；
  • 码单元：Gardiner 全表，用到才建单元格。

4.2 词候选

matchVocabulary(query)        // 按 MdC 前缀
matchVocabularyByPron(token)  // 按发音前缀
mergeWordCandidates([...])    // 合并 + 按 insert 去重 + 排序

mergeWordCandidates 不再对全量候选做全排序：它用大小为 VM_MAX_CANDIDATES = 200 的最大堆做 top-k 选择（O(n log k)），返回数组带 truncated 标记，分页栏显示「仅前 200 条」。

4.3 输入防抖与懒渲染

  • IB 的 input 事件有 50 ms 防抖（分隔符 - : } 不防抖，立即切焦点）；
  • 候选格首次可见时才渲染字形（paintCellGlyph），避免启动时上千次渲染；
  • 预览 SVG 有 LRU 缓存（500 条），单码字形缓存上限 1,000 条。

4.4 实测（7,687 条词条）

指标结果
发音匹配约 2 ms
合并 + top-200约 3 ms（8,000 个唯一候选）
单键同步耗时0 ms（防抖）
5 行候选出图约 120–150 ms
单码快速渲染7 个码约 10 ms（loadShapes）

4.5 王名检索（PharaohMatch）

js/engine/pharaoh-match.js 提供王名检索；语法 ~d<Code>~n<类别>~<Name>（两段均可选、顺序任意）；候选超过 40 页时只显示前 40 页。数据在 data/pharaohs/（pharaoh.se，CC BY 4.0）。王名候选统一渲染在 VMBox（词条形式：左列＝由转写 1:1 折叠出的拟合MdC读音，右列＝国王 · 类别 · 王朝），PDM/GM 仍只显示单字符。写入时按类别加框：Horus → <S-…-S>，Prenomen/Nomen → <-…->，其余不加框。

成员说明
PharaohMatch.search(q)~d19~RamessesII / ~Ramesses3 / 19th dynasty Ramesses
PharaohMatch.parse(q)拆出 { code, category, name, num }；category 为 o/n/p/h/g
PharaohMatch.kingsIn(code)某朝代/时期代号下的全部国王（浏览模式用）
PharaohMatch.searchEntries(q)按王名本身检索；2,333 条王名（名称/转写/MdC）全部入候选映射，返回 { king, entry }
PharaohMatch.namesFor(id)某国王的全部王名变体 { s, n, t, g, m }
PharaohMatch.categoriesFor(id)该类国王拥有的名号类别与条数

5 MdCRndr 插件 API

MdCRndr 是独立单文件渲染器（约 2,600 行），可脱离 CHEAV 嵌入其它页面：

MdCRndr.init({ fontSize: 40, injectFontFace: false });
MdCRndr.renderText(document.getElementById("out"), "S34-N35:Aa1", 48);
const { tree, invalid } = MdCRndr.parse("D21:N35");
MdCRndr.defineLigature("G39-X1", ["G39", "X1"], "G39-X1");
成员说明
init(options) / set(options) / config()初始化、运行期改配置、读取当前配置
renderText(el, mdc, fontSize)把 MdC 渲染进元素（横排）
parse(mdc) / splitLines(tree)解析成语法树 / 按 ! 切行
detectInputMode(s) / decodeCode(c) / charOf(c) / codeOf(ch)输入判定与码 ↔ 字符互转
canonicalCode(c) / canonicalize(mdc)别名码规范化（J1→AA1、Y1v→Y1a）
defineLigature(name, parts, pron)注册连字
GARDINER / LIGATURES / EM_SQUARE / visuHeight / visuWidth数据与度量
internals高级用法：renderGlyph、renderVRG、renderHRG、buildCss 等

6 扩展指南

加词条

编辑 js/database/vocabulary.js：

new Vocabulary("nfr", "F35", { en: "good, beautiful", chs: "好，美" });

变体写法：第 3 参数传 null、第 4 参数传母词汇的 MdC，释义会与母词共享同一对象。

加音素 / 定符

分别改 js/database/maps.js 的 PHONEME_TABLE 与 js/database/determinatives.js；单元池在启动时重建。

加连字

MdCRndr.defineLigature("G39-X1", ["G39", "X1"], "G39-X1");

用 & 引用：G39&X1。注意 jsesh-js 对部分 %insert 类构造尚未实现，复杂连字会回退 MdCRndr。

更新词典词表

重新跑 tools/dickson_mdc.py 生成 JSON，再跑 tools/gen_dickson_vocab.py；后者默认输出到 data/dickson/（记得保留许可头与 README）。

更新 jsesh-js

替换 lib/jsesh/jsesh.js 与 lib/jsesh/data/ 后，先跑一次冒烟测试：

nfr → Tab → Enter        // 主渲染
A29                      // GM 单码候选
<S-N35-S>                // 塞拉赫
%[orientation=vertical]  // 不应使用；竖排请走 textOrientation

7 调试与发布

本地运行

python -m http.server 8000
# 打开 http://localhost:8000/

不要用 file:// 直接打开来调 jsesh：模块 import() 在部分浏览器会因 CORS 失败。文档浮层用 #doc=instructions / #doc=for_developers 深链接。

缓存与版本

  • 改脚本后在 index.html 把 ?v=3.0.0 升一个小版本（如 ?v=3.0.1）；
  • 同步 js/ui/glyphs.js 的 BUILD，页脚会显示；
  • 版本号与日期写在页脚与 README.md 的“版本历史”里。

发布检查清单

  1. 本地 8000 端口冒烟：输入、Tab、Enter、竖排、候选翻页；
  2. 缺字形（如 A478A）显示红字而非方块；
  3. 长词（如 nbdwqd）预览不压住右侧文字；
  4. PDM / GM 单字格水平居中；
  5. git status 干净后 push，等 GitHub Pages 构建（约 30–60 s），核对页脚 Version / Build。

8 已知限制

  • 缺字形码：Dickson 词表有 22 条（16 个码）在 jsesh 数据里不存在，显示红字；A478A 即其一，词典原书也缺该字形。
  • 启动 DOM：GM 池仍会在启动时建约 4,600 个空单元格（字形懒渲染）；可改为“用到才建”以进一步压缩启动时间。
  • jsesh 未实现：%insert（含复杂 & 连字）、%hkern、%vkern；这些串会自动回退 MdCRndr。
  • 候选上限：VM 最多 200 条，超出部分不参与分页；需要更大范围时调 VM_MAX_CANDIDATES，但要重新评估排序耗时。
