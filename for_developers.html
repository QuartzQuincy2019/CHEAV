1 项目结构与加载顺序

CHEAV 是纯静态项目：无打包器、无模块系统，全部以传统 <script> 顺序加载，全局共享一个脚本作用域。

2 三步接入

① 放入文件

把 MdCRndr.js 与字体 NewGardiner.ttf 拷进你的项目（插件自带一套默认视觉度量与 Gardiner 码表，无需其它数据文件）。

② 引入并初始化

<script src="MdCRndr.js"></script>
<script>
  MdCRndr.init({
    fontUrl: "fonts/NewGardiner.ttf",   // ← 相对**页面**的字体路径
    fontSize: 40,                        // 默认字号（px）
  });

  const host = document.getElementById("out");
  MdCRndr.renderText(host, "S34-N35:AA1");   // 解析纯 MdC 并渲染
</script>

③ 得到 DOM

<div id="out">
  <span class="hie" style="font-size:40px;transform:translateY(-0.04px)">𓋹</span>
  <span class="vrg" style="width:18.16px;height:40px;justify-content:space-between;vertical-align:27.8px">
    <span class="vrg-layer" style="height:12.2px;justify-content:center">
      <span class="hie" style="font-size:40px">𓂋</span>
    </span>
    …
  </span>
</div>

插件会向 <head> 注入一个 <style id="mdcrndr-style">，内容含 @font-face 与下列类名规则 —— 因此接入方不需要另写 CSS。

4 生命周期与配置

MdCRndr.init(options?) → MdCRndr

应用配置并注入样式表。幂等：可重复调用，样式表按 styleId 复用（不会叠加多个 <style>）。未调用 init 时渲染仍可工作，但只有内联样式、缺少 @font-face 与类规则。

MdCRndr.set(options) → MdCRndr

运行期修改配置（部分覆盖），随后重建样式表。适合做「实时调参」面板：

MdCRndr.set({ fontSize: 64, vrgItemGap: 0.16, textScale: 0.5 });

返回生效配置的副本（改它不会影响插件）。

5 渲染

5.0 字形的位置与大小：排版原理

渲染不测量 DOM，也不按像素摆位；所有位置与尺寸都由字号和字体度量推出。 记住三条不变量，其余规则都能推出来：

不变量含义
1em 方格 每个字形占一个 fontSize × fontSize 的方格（下称「格」）；组、包围框的外廓也都是 1em。
只缩不放 任何缩放系数 s = min(1, 1em / 需求尺寸) —— 放不下才等比缩小，绝不放大（Faulkner 词典观感）。
单位一律 em 内边距、边框、间距、齿带全部写成 em，随字号缩放；换字号不需要改任何一处。

度量从哪来

每个码的墨迹尺寸取自字体 glyf 的 bbox，存在 visuHeight / visuWidth 里， 单位是设计单位（EM_SQUARE = 1000，即 1000 = 1em）。getMetrics(code) 返回 { height, width }。例如 A1 = 999×695（几乎满格），D21 = 305×996（扁而宽）， Z1 = 395×60（细高条）。

横排：一行若干格

  • 行容器 .RenderLine 是 flex 行、align-items: flex-end，所以各格底边对齐（同一基线）；
  • 每格宽度 = 该字形的字宽（字体 advance），不改写；相邻格不重叠；
  • 字形在自己的格里默认贴底；需要上下居中时（如独立显示、包围框内），引擎写入 transform: translateY(-(fontSize − 墨迹高)/2)，把墨迹居中到格里； 以 40px 的 A1 为例，墨迹 999/1000 已接近满格，位移只有 0.02px；像 D21（305）则上移约 14px；
  • .hie 是 inline-block，一个字形作为整体参与换行，不会从中间断开。

堆叠组（VRG）：把一个格切成若干层

组的外框永远是 1em 高，层自上而下排列；每层先算出自己的墨迹高与宽（层内元素宽度之和，相邻元素再加 vrgItemGap），然后：

总层高  totalH = Σ 层高 + vrgLayerGap × (层数 − 1)      // 默认 vrgLayerGap = 0.05em
最大层宽 maxW   = max(各层宽)
缩放    s      = min(1, 1em / totalH, 1em / maxW)          // 只缩不放
组盒高  = 1em（justify-content: space-between：首层贴顶、末层贴底）
组盒宽  = maxW × s
层内    = 单元素居中；多元素两端对齐（space-between）
层内字号 = 基准字号 × s

实测几个例子（单位：设计单位，1000 = 1em）：

写法层高 / 层宽s说明
D21:N35305/996, 150/9831.000 总层高 505、最大层宽 996，都放得下 → 不缩放，组宽 0.996em
Z1*Z1:Z1*Z1395/245 ×21.000 四开四格，不缩放；组宽 0.245em（内容窄，盒就窄）
A1:A1:A1999/695 ×30.323 总层高 3097 超高 → 整体缩到约三分之一，组宽 0.224em
D21*D21*D21305/32380.309 单层太宽 → 缩到 1em 内（组宽正好 1em）

注意组盒宽是 maxW × s，所以一个窄组不会白白占满 1em —— 这也是「A1:A1:A1 缩得很小」时 看上去仍紧贴前后符号的原因。

竖排：一列若干格

  • 列容器 .vline 宽恒为 1em，单位自上而下堆叠、水平居中；
  • 组在竖排中仍是 1em 方格内的排版，只是层变成行（HRG），几何与横排 VRG 完全一致；
  • $ 分段即分列，列自左向右排列。

包围框：外廓锁死 1em，内容按类型缩放

包围框不改变所在格的尺寸：外廓恒为 1em，内容按框的种类缩放到固定比例，腾出的空间给边框、内边距与收口件。

框内容缩放外廓构成收口件
王名圈 A0.700.70 + 0.16 + 0.06框外细座（座 + margin 占位）
塞拉赫框 S0.640.64 + 0.22 + 0.14框外字体字形尾
裸方框 h10.700.70 + 0.16 + 0.14无
堡垒框 F0.500.50 + 0.16 + 0.06 + 0.28四边雉堞齿（DOM 元素）

框外的收口件（座、尾、雉堞）用 margin 预留布局空间，因此不会压到相邻符号，也不改变框内排版。

阴影与插入文本

  • 阴影不改任何尺寸：它给 .sh-cell（高 1em；横排宽随内容、竖排宽 1em）加四层 50%×50% 的背景，纯绘制、不参与布局与度量；
  • 插入文本字号 = textScale × 基准字号（默认 0.4，40px → 16px），写成绝对 px， 垂直居中（align-self: center），不随容器 font-size 变化；
  • 连字的盒宽 = 各部件右端的最大值；部件用绝对定位按 dx / dy / scale 摆在方块内， 不参与常规流。
一句话总结：字号决定格，度量决定格内怎么摆，min(1, …) 决定要不要缩， em 决定换字号时为什么不用改任何数值。

5.1 横排排版分步图解

下面把横排的排版拆成 7 步，每步给正确与错误两张示意图（canvas 现场绘制，尺寸按 1em = 64px 折算）， 并说明这条规则为什么存在。看懂这 7 步，横排的行为就不用再猜。

⑤ 补充：s = min(1, 1em / totalH, 1em / maxW) 是怎么来的

组要装进一个 1em 方格，于是有两个互相独立的约束：高不超过 1em、宽不超过 1em。 设未缩放时的内容高为 totalH、最宽层为 maxW，等比缩放系数为 s：

约束不等式解出
高度不得超过 1ems × totalH ≤ 1ems ≤ 1em / totalH
宽度不得超过 1ems × maxW ≤ 1ems ≤ 1em / maxW
只缩不放s ≤ 1s ≤ 1

s 必须同时满足这三条，所以取三者的最小值：

s = min(1, 1em / totalH, 1em / maxW)

三点说明：

  • 为什么取 min 而不是分别压 x/y：等比缩放才不破坏字形比例；分别压扁会让符号变形，这正是要避免的；
  • 哪一个约束生效：谁更"超标"谁生效 —— 高瘦的组合由 1em/totalH 决定， 宽扁的组合由 1em/maxW 决定；两者都不超标时 s = 1（不放大）；
  • 缩放后：高 = totalH × s、宽 = maxW × s，至少有一项正好等于 1em， 另一项则 ≤ 1em（留白由 space-between 分配）。

其他1+3X1:Z1*X1*Z1 276×494 / 395×8641.0000.864em 上一下三；组宽被宽的那层撑大
其他3+1Z1*X1*Z1:X1 395×864 / 276×4941.0000.864em 1+3 的上下镜像，组宽相同

单层组的两副面孔（吅 这类 "2"）

只有一层的组（如 D21*G43）在横排下有两种完全不同的表现，这点很容易踩坑：

场合DOM表现
横排顶层2 个 .hie，无 .vrg 退化为普通序列：两个字各占 1em、顺序排开，不生成组盒、不缩放。 所以 D21*G43 与 D21-G43 在顶层渲染结果完全相同
嵌在多层组内.vrg-layer 内 作为该组的一层，按组的 s 缩放；此时才受 1em 方格约束（D21*G43 的 s = 0.557）
竖排1 个 .hrg 始终生成盒：竖排需要知道"哪些单位属同一行"，因此单层组不会被展开

换句话说：* 在顶层只是"顺序无所谓"的写法；要让它成为真正的四开组，必须让它处在多层组里 （例如 D21*G43:N35），或放进竖排。

层与层为什么不会重叠

组内布局用的是 justify-content: space-between：首层贴顶、末层贴底，中间各层把剩余空间等分。 所以设层高为 hᵢ' = hᵢ × s（缩放后），则

层间距 gap = (1em − Σhᵢ') / (层数 − 1)      // 层数为 1 时不适用
第 i 层的顶部 yᵢ = 上一层的 y + h' + gap

由此可推出几个直觉结论：

  • 层数越多，层间空隙越窄：亖（四层，Σh' 已接近 1em）的 gap 只剩几个像素，四层几乎连成一条； 三（三层，总层高 550 远小于 1em）的 gap 就很大，三层之间明显拉开；
  • 重叠在实现里不可能发生：gap ≥ 0 且各层顺序累加，最坏情况（Σh' 超过 1em）由缩放 s 提前拦截 —— 这正是 s = min(1, 1em/totalH, 1em/maxW) 存在的意义；
  • 上图里的重叠是画图脚本的 bug，不是引擎行为：早先版本把中间层各自"居中"到剩余空间， 三层以上就会互相压住；现已改为按上面公式顺序堆叠。

从层结构能直接读出什么

  • 层数决定要不要缩：总层高 = Σ层高 + 0.05em×(层数−1)。三（N35×3）总高 550 → s=1； 亖（O34:N37:Z9:Y1）总高 1328 → s=0.753；𠾅（三层五格）总高 1525 → s=0.557；
  • 组宽由最宽的层决定：吕的两个符号都接近 1em 宽 → 组宽正好 1.000em； 三只 0.983em（N35 宽 983）；品 0.956em；亖 的每层宽 466–1000，最终 0.753em；
  • 宽符号更容易触发缩放：吅/㗊/𠾅 都含 G43（宽 675）与 D21（宽 996），层宽 1796 → 一律 0.557； 这是「两个宽字并排必定缩」的直接体现；
  • 层内多格两端对齐、单格居中：品的下层 G43+X1 贴住左右边缘；倒品的下层 N1 单格居中； 𠾅 是"贴边 / 居中 / 贴边"；
  • 竖排（HRG）下同一写法换语义：* 变「同一行并列」、: 变「换行」， 但层结构、层高、层宽与缩放公式不变。
书写规则：四开组内不能用 -（那是组间分隔），所以「品」只能写 D21:G43*X1， 不能写 D21-G43*X1；层内元素之间只允许 *。
名称说明：吅 / 吕 / 三 / 品 / 倒品 / 㗊 / 亖 / 𠾅 是按汉字字形起的类比名， 不是埃及学或 MdC 规范的术语；正式场合直接写层结构（如 2+1+2）。

9 连字注册

                
MdCRndr.defineLigature(name, parts, pron?) → { name, parts, pron }

                
注册或覆盖一个连字。名字是码序列（用 - 连接 1–3 个字符，: 会被规范化为 -），随后即可在 MdC 中用 {名字} 引用。

                

                    
part 字段单位含义

                    
code—部件字符码（Gardiner 或十六进制）

                    
dxem相对连字方块左下角的水平偏移（向右为正）

                    
dyem垂直偏移（向上为正）

                    
scale倍率相对 1 em 的缩放（1 = 原始大小）

                

                
parts[0] 习惯上作为基准部件（dx=0, dy=0, scale=1），渲染时按「独立字」处理（在 1 em 轨道内上下居中）；其余部件贴基线定位。连字盒宽度取各部件墨迹右端的最大值，而不是固定 1 em —— 这样连字与前后字形之间不会留空档。

                
// 例：鹌鹑雏 + t（tw）
MdCRndr.defineLigature("Q3-G43", [
  { code: "G43", dx: 0.0, dy: 0.0,  scale: 1.0 },
  { code: "Q3",  dx: 0.0, dy: 0.15, scale: 0.45 },
], "pw");

MdCRndr.set({ ligatureDebug: true });   // 调试：显示每个部件的红色边框
MdCRndr.renderText(out, "{Q3-G43}");

    11 MdC 语法规范
    
                
    
                    
    记号规则示例
    
                    
    码Gardiner 码（首字母大写，A45a 式变体）或 5 位十六进制（1313F）D58-G43
    
                    
    -四开组之间的横排（组间是普通序列关系；堆叠组内部不允许 -）同上
    
                    
    *同一四开组内并列（横排）。与 : 相邻使用即构成一个堆叠组W24*X1:N1
    
                    
    :下移一层（竖叠）；相邻的 * / : 串构成一个堆叠组（VRG），层自上而下D21:N35
    
                    
    { }连字引用；名字内 : 与 * 归一化为 -；整块占 1 em 方格{I10-D46}
    
                    
    < >插入文本；内部空白原样保留，\<、\> 转义；不参与「非法」判定F35-<good>
    
                    
    ( )词（lexis）—— 目前按普通序列展开，保留语法位(D58-G43)
    
                    
    $手动换行；splitLines 据此分段D21-$-D46
    
                    
    空格组外空白一律忽略（宽容）；< > 内保留—
    
                
    

    
                    阴影：组#1234。解析时 # 作为分隔符（parseCode 的终止字符集），
                    由 parseQuadrat 记录到 items 的 shadow，收尾时挂到整个四开组：
                    单单位 → {type:"shaded"} 包装；组 → vrg.shadow。
                    渲染用 renderInShadedCell 先包一个 1em 见方的 .sh-cell（阴影按此方格划分四象限，而非字形行盒），再调 applyShadow(el, digits)：每个分区是一层
                    repeating-linear-gradient(45deg, …)，background-size: 50% 50% +
                    对应角的 background-position，no-repeat；纯背景层，不参与布局与度量。

    
                
    
                    包围框（MdC 扩展）：<- … ->（王名圈）、<S- … ->（塞拉赫框）、
                    <h1- … -h1>（裸方框，非正式名）、<F- … ->（堡垒框，非正式名；四边雉堞状方块齿，段长 0.12em / 间隔 0.20em）。解析为 { type:"enc", kind, units }，
                    嵌套计入 invalid；渲染为 .enc + .enc-A / .enc-S / .enc-h1，竖排加 .enc-v。
                    几何全部用 em 推导（stroke 0.05 / 0.07，内容 0.70 / 0.64，外廓恒为 1em），不做测量、不做重复拼贴。
                    竖排列序为自左向右（.vtext 用 flex-direction: row），列内自上而下。

    
                
    
                    严格配对：{ }、( )、< > 必须同种闭合。
                    写成 {D21:G43) 或缺闭合符时，该片段计入 parse().invalid；顶层若残留多余字符同样计入。
                
    
                
    
                    引擎不认识的输入：发音（nfr）、定符名（;eye）、词条名一律判为非法 ——
                    渲染引擎只吃「纯 MdC 渲染串」。CHEAV 在送入正文之前用 PIC 模块把发音换成码，因此正文里永远是合法的。
                
    
                
    
                    字体缺失的码不是非法输入：语法合法（Gardiner 形状的码或圣书体区十六进制）但字体没有对应字形的，
                    解析为 { type: "unsup", code } —— 计入 invalid 不再发生，
                    渲染为一个 1 em 方块占位、框内写码名（.unsup，可经
                    unsupportedClass 改名），并按 1 em 方块参与度量与堆叠组缩放，
                    因此在序列、堆叠组层内、插入文本旁边都能落在正确位置。
                    真正非法的仍然只有「不是码的串」（发音 nfr、定符名 ;eye）与括号错误。
                
    
                
    
                    码名别名：规范名是 AA…／Aa…（Unicode AA 组）；
                    J… 是等价的非规范简写（Gardiner 表无 J 组），Y1v ≡ Y1a。
                    引擎查表两种写法都接受，但写入正文前一律换成正式名：
                    canonicalCode("J1") → "AA1"、canonicalize("J1-A1") → "AA1-A1"、
                    canonicalize("J80") → "Aa80"。<…> 文本区内不改写；
                    连字名 {J1-D52-X1} 会先规范化再查连字表。
                
    
            
    

            
            
    
                
    12 渲染几何
    
                
    一切以「方块（quadrat）」为基准：1 quadrat = 1 em = fontSize px。
    
                
    堆叠组（VRG）
    
                
    层高取该层最大墨迹高，层间保留 vrgLayerGap（默认 0.05 em），层内元素间保留 vrgItemGap（默认 0.125 em，计入层宽）。统一缩放系数：
    
                
    s = min(1, EM_SQUARE / 总层高, EM_SQUARE / 最大层宽)
    
                
    即只缩不放大：符号保持原比例，仅当整组超出 1 em 方块时才等比缩小（Faulkner 词典观感）。组宽 = 最大层宽 × s，层内元素两端对齐（space-between；单元素层居中）。
    
                
    独立字符（IS）
    
                
    在 1 em 轨道内垂直居中：transform: translateY(-(fontSize − 墨迹高)/2)。若你要把字形行内嵌排进正文，去掉该位移即可让墨迹直接坐在正文基线上：
    
                
    .Prose .hie { transform: none !important; }
    
                
    行内基线（inlineBaseline，默认 true）
    
                
    堆叠组是 inline-flex，其基线取首层基线；若不补偿，整盒会沉到正文基线以下。引擎按 fontSize − 首层高 写入 vertical-align，使盒底（= 末层基线）落在正文基线上。在 flex 排版中 vertical-align 被忽略，因此对块级渲染区无影响。
    
                
    插入文本
    
                
    字号为 textScale × 基准字号（默认 0.4），引擎写成绝对 px 内联样式，因而不依赖宿主容器的 font-size；上下居中由 align-self: center 提供。
    
                
    竖排：VRG → HRG（水平渲染组）
    
                
    竖排时文字自上而下成列，$ 分段即分列，列自左向右排列（先读最左一列、列内自上而下）；每列宽度恒为 1 em（.vline）。
    
                
    组在竖排中改称 HRG（水平渲染组），但几何与横排 VRG 完全相同：
    
                
    *  同一"层"内的单位左右并列 —— 竖排中即同一行内并列
:  下移一层 —— 竖排中即换到下一行（仍属同一个组，组宽仍限 1 em）
-  四开组之间的横排 —— 竖排中即换到下一"行"（新的组）
    
                
    区别只在命名与流向：横排里 VRG 是一条"竖带"（层自上而下堆叠），竖排里同一个组占的是一条"横带"（一行），
                    故称水平渲染组。缩放、层间距（vrgLayerGap）、层内两端对齐与单符号居中全部沿用 VRG 的规则
                    （s = min(1, 1em/总层高, 1em/最大层宽)）。
    
                
    解析约定：为让竖排知道哪些单位应在同一行，* 连接的同层组在解析树中保留为单层
                    { type:"vrg", layers:[…] }（横排渲染与度量都不变：render 对单层组仍按序列展开，
                    unitMetrics 也不计层内间隙）。
    
                
    入口是 MdCRndr.renderVerticalText(el, text, size) —— 它独立于 renderText，
                    同一个 MdC 串前者出竖排、后者出横排。MdCRndr.set({ vertical: true }) 不会把
                    renderText 变成竖排；options.vertical 只用作渲染时的朝向标志
                    （包围框据此把内容改为纵向、把座 / 尾移到底部），要竖排必须调用 renderVerticalText。
    
                
    CHEAV 中竖排只作用于正文渲染区；缓冲区、缓冲区预览与匹配区仍走横排的 renderText。
                    <文本> 片段在竖排中带 writing-mode: vertical-rl。
    
                
    在宿主页面里嵌入竖排
    
                
    样式（含 @font-face）在首次渲染时自动注入，所以最小用法不需要先调 init()；
                    若需要改字体路径、类名前缀等配置，再显式 init() / set() 即可（重复调用是幂等的）。
    
                
    <div id="wall"></div>
<script src="js/plugin/MdCRndr.js"></script>
<script>
// 竖排：自上而下成列，$ 分段即分列，列自左向右
MdCRndr.renderVerticalText(document.getElementById("wall"), "A1-A1-$-D21:N35-$-<S-A1-N35->", 40);
// 想换字体或类名时再初始化（可选）
// MdCRndr.init({ fontUrl: "./fonts/NewGardiner.ttf" });
</script>
    
                
    容器只需是普通块级元素：竖排整块是 .vtext（inline-flex，列向为 row），
                    每列是 .vline（1 em 宽）。窄容器会自动换行，不需要额外设置。

IB 内容被替换为码串 ──入流（enterInflow）──→ PIC 就地转换（engine/pic.js）
   ↓ Enter 确认（commitAll）
正文文本框 ──parseInput()──→ 单位树 ──render()──→ 渲染区 DOM

    15 扩展指南
    

                
    加词条（database/vocabulary.js）
    
                
    new Vocabulary("pron", "MdC 渲染串", { en: "meaning", chs: "释义" }),

// 例：
new Vocabulary("nfr",  "F35",              { en: "beauty", chs: "美丽" }),
new Vocabulary("anx",  "S34-N35:AA1",    { en: "live, life", chs: "生命" }),
new Vocabulary("tw",   "{X1-G43}",         { en: "you", chs: "你" }),
    
                
    
                    第二参数是 MdC 渲染串（不是数组）。释义对象必须作为第三参数 —— 若误写进数组会被判为非法数据。
                
    

                
    加音素（database/maps.js 的 PHONEME_TABLE）
    
                
    音素是单点注册：只在这里登记「发音 → Gardiner 码」，vocabulary.js 会自动生成音素实例。
                    注意表中写的是 码而不是字符（字符由码经 hg() 得到），行内第 1 个码即该发音的主码（PIC 与 hm() 取它）。
    
                
    const PHONEME_TABLE = [
  ["A", "G1"],                       // 一音一码
  ["nw", "W24", "U19"],              // 同音异形（W24 为主码）
  ["smA", "F36"],                    // 一形多音：另一行再登记 ["zmA", "F36"]
];
    

                
    加定符（database/determinatives.js）
    
                
    { code: "D4", names: ["eye", "see"] },     // 多个名称指向同一码；反查不限
    

                
    加连字
    
                
    几何写在插件（MdCRndr.defineLigature），语义实例由 database/ligatures.js 建立。内置连字定义随插件分发；项目内新增可调用：
    
                
    // 浏览器控制台
defineLigature("Y1-Z2", [
  { code: "Y1", dx: 0,    dy: 0,    scale: 1 },
  { code: "Z2", dx: 0.45, dy: 0.55, scale: 0.7 },
], "pron");
LIGATURE_DEBUG = true;    // 打开部件边框，反复调 dx/dy/scale
CHEAV.refresh();          // 或在 IB 中输入 {Y1-Z2} 直接看预览
    

                
    词条维护脚本（tools/entries.js）
    
                
    查询与增补 Vocabulary / Determinative / PHONEME 的命令行工具，
                    自动处理排序、备份与写后复核（写盘后会重新载入并校验全部词条 MdC）：
    
                
    node tools/entries.js "/s -v /p anx"       # 查询：词汇中发音含 anx
node tools/entries.js "/s -d -a"          # 查询：列出全部定符
node tools/entries.js                     # 交互模式（:h 帮助，:q 退出）
node tools/entries.js --dry-run "/a …"    # 只预览不写盘

# 查询：/s [-a] [-s] [(-v|-d|-p)] [-e] [/p [-e] 发音] [/g [-e] 码] [/r [-e] MdC] [/m [-e] 释义|定符名]
#   (-v|-d|-p) 后的 -e = 全局一致匹配；筛选器后的 -e 只作用于该筛选器
/s -v -e /p anx /g S34        # 发音确切为 anx，且码含 S34
/s -v /p anx /g -e S34        # 发音含 anx，且码恰为 S34

# 添加：/a (-v|-d|-p) [-prim] [/p 发音] [/g 码] [/r MdC] [/m …] [/h 象形字]
/a -v /p whn /r "G43-O4:N35-O118" /m -en "throw down" -chs "推倒"
/a -p -prim /p a /g D36       # 音素：a 的主码设为 D36
/a -d -prim /g C1 /m Ra       # 定符：C1 的名称 Ra 排到第 1 位
    
                
    排序规则：词汇按 MdC 自然序（忽略 - : * 等结构符、数字按数值比较）；
                    定符按 Gardiner 码自然序；音素按首字母分组（同组内不强制次序）。
                    发音匹配区分大小写（S 与 s 是不同音素），码 / MdC / 释义不区分大小写。
                    /h 只用于把给出的象形字与 MdC 渲染结果比对校验，不写入数据。
    

                
    词汇变体
    
                
    互为变体的词汇，释义一定相同 —— 实现上是让变体的 meaning 指向母词汇的
                    同一个对象（装配期在 vocabulary.js 里完成链接），因此改母词汇的释义即全族同步，
                    结构上不可能不一致。变体在文件里写成第 3 参数为 null、第 4 参数为母词汇 MdC：
    
                
    new Vocabulary("pr", "O1",   { en: "house", chs: "房屋" }),   // 母词汇：携带释义
new Vocabulary("pr", "O1-Z1", null, "O1"),                      // 变体：同音、共享释义
new Vocabulary("pr2", "O1*Z1", null, "O1"),                     // 变体：可另给发音
    
                
    应用侧接口：Vocabulary#variantOf（母词汇 MdC）、#parent（母词汇实例）、
                    #isVariant；variantsOf(mdC) 取某母词汇的全部变体、
                    variantFamily(mdC) 由任一成员反查 { parent, members }。
                    变体是独立词条，照常参与 VMBox 匹配，只是释义取自母词汇。
    
                
    # [A] 为已存在的词汇添加变体（母词汇必须恰好 1 个匹配）
/a -v -v /bf <搜索条件> /ef [/p 发音] /r <MdC>
/a -v -v /bf /p anx /r -e "S34-N35:AA1" /ef /r "S34-N35:AA1-Z1"   # 省略 /p → 与母词汇同音

# [B] 添加新词汇与它的变体（第 1 项为母词汇；第 2 项起可省略 /p，则与前一项同音）
/a -v -V /m <释义> /bli # /r <MdC> /p <发音> # /r <MdC> # … /eli
/a -v -V /m -en "house" -chs "房屋" /bli # /r "O1" /p pr # /r "O1-Z1" # /r "O1*Z1" /p pr2 /eli

# 修改（目标必须恰好 1 个匹配；未指明项维持原样）
/m (-v|-d|-p) [-V] /bf <搜索条件> /ef <修改项…>
/m -v -V /bf /r -e "O1" /ef /m -en "house" -chs "房屋"   # -v -V：母词汇与全部变体一起改释义
/m -v    /bf /p pr /r -e "O1-Z1" /ef /p pr9             # 改某一变体的发音
/m -d    /bf /g -e C1 /ef /m -add sun_god               # 定符：增加名称（-set/-del 亦可）
/m -p    /bf /p a /g -e D36 /ef -prim                   # 音素：设为主码
    
            
    

            
            
    
                
    16 调试与陷阱
    
                
    
                    
    陷阱说明
    
                    
    
                        改了 JS/CSS 没生效
                        浏览器缓存。硬刷新：Ctrl+F5。
                    
    
                    
    
                        字体显示为方框
                        fontUrl 相对页面文档解析，不是相对 JS 文件。跨目录引用时写对路径。
                    
    
                    
    
                        兼容层绑到 undefined
                        兼容层从插件取名字，若插件已删除该导出（如 internals.parseRenderingCode），绑定即为 undefined 且不报错。改动插件导出后请一并检查兼容层绑定表。
                    
    
                    
    
                        加载顺序
                        插件必须在所有模块之前；ui/apply.js 必须在 <body> 末尾（需 DOM 就绪）。兼容层之间不要重复声明同名 const（同一脚本作用域会抛错）。
                    
    
                    
    
                        单例
                        插件是单例：set() 改的是全局配置，会影响同一页面上所有渲染。需要多套外观时请在容器上用 CSS 覆盖，而不是切换配置。
                    
    
                    
    
                        连字宽度
                        盒宽 = 部件墨迹右端最大值（非固定 1 em）。若连字与前后字形紧贴得不理想，先检查 parts 的 dx/scale。
                    
    
                    
    
                        行内嵌排
                        独立字符默认在 1 em 轨道内居中，直排进段落会显得「浮起」。用 transform: none 覆盖即可贴正文基线；堆叠组由 inlineBaseline 自动补偿。
